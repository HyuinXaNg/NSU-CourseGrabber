# 🏸 抢课助手

成都东软学院「体育项目」选课辅助工具 —— 可视化操作，点按钮开始，结束后明确告诉你**是否抢到**、以及**没抢到的原因**。

抢课这件事的痛点是：手动 F5 拼手速容易错过开抢瞬间，抢完还不知道到底成没成。本项目把这两件事都解决掉：准点毫秒级触发，结果用大字号明确显示。

**⚠️ 请先阅读文末的[免责声明](#-免责声明)。**

**使用流程**

1. 双击 `启动桌面版.bat`（或运行 `python 抢课助手.pyw`）
2. 程序自动打开一个 Chrome 窗口并跳转到选课网址
3. **在 Chrome 里手动登录**教务系统，切到「体育项目」标签页
4. 回到桌面窗口，点 **`▶ 开始抢课`**
5. 结果实时显示在窗口顶部

> 登录状态保存在 `.chrome-profile/`（**该目录已在 `.gitignore` 中，切勿提交**），下次启动无需重新登录。
>
> 程序**不接触你的账号密码**，登录完全由你在 Chrome 里手动完成。
> Chrome 也是用你本机已安装的，**不会额外下载浏览器**。

### 方式二：浏览器内 GUI（零安装）

不想装 Python 的话，把 `grab_course.gui.js` 整个文件的内容粘进浏览器即可。

打开选课页面后，任选一种：

| 方式 | 步骤 |
|---|---|
| **DevTools Snippets**（最省事） | `F12` → `Sources` → `Snippets` → `New snippet` → 粘贴 → `Ctrl+S`。以后右键 → **Run** |
| **Tampermonkey** | 新建脚本 → 粘贴 → 保存，打开选课页自动出现界面 |
| **控制台** | `F12` → `Console` → 粘贴 → 回车（首次需先输 `allow pasting`） |

界面上同样有「▶ 开始抢课」按钮和结果状态条。

### 方式三：控制台版（无界面，最轻量）

把 `grab_course.js` 粘进控制台即可，通过 API 操作：

```js
__GRAB__.scan()      // 扫描一次，返回识别到的课程卡片
__GRAB__.dump()      // 识别不到课程时用它排错
__GRAB__.stop()      // 停止
```

## 🔍 工作原理

### 1. 用文本特征定位，而不是 class 名

教务系统一改版，class 名就变了，所以脚本只认**文案格式**：

```
[083-羽毛球][T9000001]李老师         <- 卡片标题
已选容量：0/67                         <- 容量（也兼容 已选：0/67、剩余名额：5）
选择                                   <- 按钮文案（精确匹配，不会误点「教学班详情」）
```

定位流程：全页找文案正好是「选择」的元素 → 逐层向上找第一个含卡片标题格式的祖先 → 从卡片文本里解析课程名、教师、已选/容量。

### 2. 判定"有空位"

```
已选 < 容量  →  有空位
已选 = 容量  →  已满，安静等下一轮，不做任何点击
```

### 3. 桌面版是个"遥控器"

桌面窗口**不重写抢课逻辑**：

```
Playwright 启动 Chrome
    → 打开选课网址 → 注入 grab_course.gui.js
    → 点「开始抢课」时调用 __GRAB_GUI__.start()
    → 每 0.4 秒读一次 __GRAB_GUI__.result()，显示到窗口上
```

好处是抢课逻辑只有一份，桌面上显示的判定结果**和页面内完全一致**，不存在两套实现跑偏。

### 4. 准点开抢

```
读 HTTP Date 响应头  →  算出本机时钟偏差  →  按服务器时钟对齐
粗略等待 → 20ms 细步逼近 → 5ms 逼近 → 到点瞬间触发
到点后 4 秒爆发期（每 500ms 重试一次），之后回落到 2 秒常规轮询
```

实测落点误差约 **10ms**。爆发期刻意不设成 100ms 级——教务服务器是全校共用的。

## ⚙️ 配置

### 桌面版

界面上直接改，自动保存到 `抢课助手配置.json`。

### 浏览器版

`grab_course.gui.js` 的 `DEFAULTS`：

```js
keywords: '羽毛球',      // 逗号分隔可多个：'羽毛球,乒乓球'
atTime: '',              // '' = 点按钮立即抢；'13:00:00' = 准点开抢
dryRun: false,           // true = 只识别不点击（建议先用它确认能认对课程）
intervalMs: 2000,        // 常规轮询间隔
jitterMs: 800,           // 随机抖动，避免固定频率
burstMs: 4000,           // 到点后的爆发期时长
burstIntervalMs: 500,    // 爆发期重试间隔（别低于 300）
maxMinutes: 120,         // 最长运行时长，到点自动停
beep: true,              // 成功时响一声
```

也可以用控制台 API 临时改：

```js
__GRAB_GUI__.settings.burstIntervalMs = 800;   // 改完点一次「开始」即持久化
```

## 🧪 测试

```bash
# 全部测试（Windows 直接双击 运行测试.bat）
node test_gui.js               # 21/21  GUI 元素 / 开始按钮 / 结果条各状态
node test_multi_target_all.js  #  3/3   一轮只抢一门（三个实现横向对比）
node test_max_minutes.js       #  4/4   时长上限（含 1 个反向对照）
node test_false_success.js     #  6/6   成败判定（反向 + 正向）
node test_parse.js             #  9/9   解析逻辑
# ... 共 12 个 Node 测试

python test_desktop_ui.py      # 19/19  桌面版 UI 层
python test_desktop_e2e.py     #  2/2   端到端：真 Chrome + 本地假选课页
```

### 测试设计上的几个刻意选择

- **反向对照**：验证「时长上限会停」时，同时跑一遍"把上限检查剥掉"的版本，确认它**不会**停——否则这个断言可能是假通过的。
- **正向对照**：修「`选课未成功` 被误判成成功」时，同时验证真实提示 `选课成功` **仍然**能被识别——否则会变成"永远判不成功 → 无限重试"，比原 bug 更糟。
- **跨实现一致性**：同一类逻辑在三个实现里各写了一遍，只测其中一个文件会漏。所以关键断言会在三个实现上同时跑。
- **端到端不等真网站**：`test_desktop_e2e.py` 造一个本地假选课页，让 Playwright 走完「启动 Chrome → 注入脚本 → 点选择 → 读回结果」全程，不依赖校园网。

<details>
<summary>开发过程中修掉的 12 个缺陷（点击展开）</summary>

| # | 问题 | 后果 |
|---|---|---|
| 1 | 引用了裸的 `CONFIRM_TEXTS`，而它定义在 `CONFIG` 内 | **致命**：抛 `ReferenceError`，且异常逃逸导致轮询循环点一次就死 |
| 2 | `realClick()` 既 `dispatchEvent('click')` 又调 `el.click()` | 每次点击触发 2 个 click 事件，可能被判「重复提交」 |
| 3 | 兜底确认定时器在准点待命期间也在跑 | 开抢前会误点页面上任何「确定/确认/提交」按钮 |
| 4 | 自动确认不区分按钮位置 | 可能点到筛选弹窗，甚至退课确认键 |
| 5 | `start()` 无重入保护 | 连点两次产生多个并行轮询循环，停不干净 |
| 6 | `stop()` 后状态不复位 | 停止后无法重新开始 |
| 7 | 爆发期 250ms × 5s = 20 次连点 | 对全校共用的服务器过于激进 |
| 8 | `MutationObserver` 监听整个 `body`，而 `renderList()` 自己就改 DOM | **无限自我刷新死循环** |
| 9 | 遍历所有有空位的课程逐个点击 | 多教学班时**一次选上多门体育课** |
| 10 | `destroy()` 没清定时器、没断开观察器 | 界面移除后仍持续重建列表，白白烧 CPU |
| 11 | 某个实现漏了最长运行时间上限 | 无人值守时无限轮询服务器 |
| 12 | 成功判定用子串匹配 `/成功/` | **`选课未成功` 被判成成功** —— 用户以为抢到了、不再重试，实际什么都没选上 |

以上每一条都是先写出能复现它的失败测试、再改代码、最后跑全量回归确认没有改坏别处
</details>

## ❓ 常见问题

<details>
<summary><b>双击 .js 文件弹出「Windows Script Host 语法错误 800A03EA」</b></summary>

Windows 上双击 `.js` 不是"打开"也不是"用 Node 运行"，而是交给 **Windows Script Host (WSH)**——它内置的 JScript 引擎是 1999 年 ES3 时代的，不认识 `const`、箭头函数、`async await`，也没有 `require`。

实测对照：

| 文件内容 | WSH 结果 |
|---|---|
| 纯 ASCII 注释 + `const` | ❌ 语法错误 |
| 中文注释块 + `var` | ✅ 正常通过 |
| 中文注释块 + `const` | ❌ 语法错误 |

所以根因是 `const`，**不是中文**。

| 你想做的事 | 正确做法 |
|---|---|
| 运行测试 | 双击 `运行测试.bat`，或 `node test_xxx.js` |
| 看脚本内容 | 双击 `打开抢课脚本.bat`，或右键 →「打开方式」→ 记事本 |
| 用抢课脚本 | **它不能双击**，要粘进浏览器 |

**记住一条：`.js` 文件永远不要双击。**
</details>

<details>
<summary><b>注入后提示「没找到课程卡片」</b></summary>

执行 `__GRAB_GUI__.dump()`（会在控制台列出页面上所有「选择」按钮及其卡片文本），把输出发到 Issues。

最常见两个原因：

- **没切到「体育项目」标签页** —— 脚本只能看到当前标签页
- **课程在分页的第 2 页** —— 脚本只能看到当前页，先翻页或用页面搜索框过滤
</details>

<details>
<summary><b>桌面版打不开选课网站</b></summary>

程序用的 Chrome 走的是系统网络，如果你的浏览器是透过代理或 WebVPN 才能访问，请把 **WebVPN 的完整地址**填进「选课网址」框，再点「🌐 打开网址」。

反过来，如果选课站只在校内网可达而当前不在校园网，任何形式都跑不了——这是网络问题，不是脚本问题。
</details>

<details>
<summary><b>怎么确认脚本能正确识别课程？</b></summary>

先勾上 **「演练模式」**（或把 `dryRun` 设为 `true`），它只识别不点击。日志里会打印识别到的课程、教师、已选/容量。确认无误后再关掉。
</details>
